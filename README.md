# מערכת ביקורות וחוויית לקוח

מערכת עצמאית (לא וורדפרס) לאיסוף משוב מלקוחות והגדלת ביקורות בגוגל:
הלקוח סורק QR, מדרג, עונה על שאלות קצרות שמותאמות לדירוג שלו, ומקבל את המסך המתאים.

## הזרימה

```
סריקת QR / קישור אישי
        │
        ▼
   דירוג 1–5 ★
        │
   ┌────┴─────┐
 מרוצה       לא מרוצה (מתחת לסף שנקבע בקמפיין)
   │           │
שאלות קצרות    שאלות "מה לא עבד" + טופס פרטי קשר
   │           │
כפתור גדול     פנייה נפתחת בלוח הבקרה + Webhook להתראה
לביקורת בגוגל  (קישורי הביקורת הציבוריים עדיין מוצגים, בקטן)
+ פלטפורמות
  נוספות
```

### למה לקוח לא מרוצה עדיין רואה קישור לגוגל?
גוגל אוסרת במפורש "Review gating", כלומר לשלוח לביקורת ציבורית רק לקוחות מרוצים.
עסק שנתפס בזה עלול לאבד ביקורות ואף לקבל השעיה של הפרופיל. גם ה-FTC בארה"ב מגביל את זה.
לכן המערכת **מציעה ללקוח הלא מרוצה קודם כל ערוץ פרטי** (טופס פרטים וחזרה מהנהלה),
אבל לא מסתירה ממנו את האפשרות לכתוב ביקורת פומבית. זה מקבל את רוב התועלת בלי הסיכון.

## פיצ'רים

- **ריבוי עסקים**: חשבון אחד מנהל כמה עסקים או לקוחות, כל אחד עם מיתוג ונתונים נפרדים.
- **קמפיינים**: לכל סניף, עמדה או ערוץ יש קישור ו-QR משלו, סף "מרוצה" משלו, שאלות וטקסטים.
- **בונה שאלות**: בחירה אחת, בחירה מרובה, טקסט חופשי, NPS. כל שאלה מוצגת לכולם, רק למרוצים או רק ללא מרוצים.
- **QR**: הורדה כ-PNG/SVG ושלט מעוצב להדפסה.
- **מעקב מקור**: `?src=table-4` בקישור או QR לפי מקור, כדי לראות מאיזה שולחן, קופה או עובד מגיעים הדירוגים.
- **בקשות אישיות**: קישור אישי עם שם הלקוח, שליחה בוואטסאפ או SMS בלחיצה, ומעקב אם נפתח ואם דירג.
- **ניהול פניות**: כל לקוח לא מרוצה הוא פנייה עם סטטוס (חדש / בטיפול / טופל), הערות פנימיות וכפתור וואטסאפ או חיוג ללקוח.
- **לוח בקרה**: סריקות, דירוגים, אחוז המרה, דירוג ממוצע, NPS, קליקים לביקורת, מגמה יומית, התפלגות, "מה הלקוחות אומרים" ומקורות.
- **מעקב קליקים**: כל יציאה לגוגל או לפלטפורמה אחרת נספרת.
- **Webhook**: התראה ל-Make / Zapier / n8n על כל משוב, כדי לשלוח הלאה לוואטסאפ, מייל, סלאק או CRM.
- **ייצוא CSV** (נפתח נכון באקסל בעברית).
- **עברית ואנגלית** בסקר, RTL מלא ומותאם לנייד.
- **אבטחה**: סיסמאות scrypt, הגנת CSRF, הפרדה מלאה בין עסקים, Rate limiting, CSP, הגנה מהזרקת נוסחאות ל-CSV.

## הרצה

דרוש Node.js בגרסה 22.5 ומעלה (משתמש ב-SQLite המובנה, בלי מסד נתונים חיצוני).

```bash
npm install
npm run seed     # אופציונלי: חשבון דמו עם נתונים, demo@example.com / demo12345
npm start        # http://localhost:3000
npm test
```

### משתני סביבה

| משתנה | ברירת מחדל | תיאור |
|---|---|---|
| `PORT` | `3000` | פורט |
| `DB_FILE` | `data/reviews.db` | קובץ מסד הנתונים |
| `PUBLIC_URL` | לפי הבקשה | כתובת האתר (משמשת בקישורים וב-QR), למשל `https://reviews.example.com` |
| `ALLOW_SIGNUP` | `true` | `false` סוגר הרשמה אחרי המשתמש הראשון |
| `SECURE_COOKIES` | `false` | `true` בפרודקשן מאחורי HTTPS |
| `TRUST_PROXY` | ריק | `1` כשהשרת רץ מאחורי Nginx / Cloudflare וכו' |

```

  server.js          נקודת כניסה

  notify.js          Webhook
  routes/public.js   הסקר ללקוח: /r/:slug → /f/:token → /t/:token → /go/:token/:platform

  views/             תבניות HTML
public/style.css
test/flow.test.js    בדיקות מקצה לקצה
```
