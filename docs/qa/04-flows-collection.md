### FLOW-016: יצירה ועריכה של קמפיין

**מטרה:** קמפיין = קישור + קוד QR + סקר. ממנו לקוחות מדרגים, ומרוצים מופנים לגוגל.
**Actors:** OWNER / MANAGER
**Trigger:** "איסוף ביקורות" ← "קמפיין חדש" (או צעד בצעדים הראשונים).
**Preconditions:** מנהל ומעלה.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | USER | בוחר תבנית לפי סוג עסק (כללי, מסעדה, יופי, קליניקה, קמעונאות, שירותים, אירוח) ושפה | טופס עם שאלות מוכנות לתבנית | — |
| 2 | USER | ממלא: שם, שפה, סף "מרוצה", קישור ביקורות גוגל, קישורים נוספים, שאלות, טקסטים, תזכורת, שאלת הסכמה לפרסום, שאלת "מי נתן שירות" | בדיקות | — |
| 3 | SYSTEM | שומרת | מעבר לעמוד השיתוף (קישור, QR, שליחה) | Campaign `active` |
| 4 | USER | עורך קמפיין קיים | אפשר גם להשבית (Active/Inactive) | Campaign updated |

**Business Rules**

| ID | חוק |
|---|---|
| BR-060 | שם קמפיין חובה (עד 100 תווים) |
| BR-061 | סף מרוצה: 2-5 (ברירת מחדל 4). דירוג ≥ סף = מרוצה |
| BR-062 | קישור גוגל: קישור ביקורת תקין או Place ID. ערך לא תקין: "קישור הגוגל / Place ID לא תקין" |
| BR-063 | עד 8 קישורים נוספים (כותרת עד 40 תווים + כתובת תקינה). שורה חלקית נמחקת בשקט |
| BR-064 | עד 20 שאלות. סוגים: בחירה אחת, בחירה מרובה, טקסט חופשי, NPS 0-10. לכל שאלה: קהל (כולם / מרוצים / לא מרוצים), חובה כן/לא, עד 12 אפשרויות. שאלת בחירה בלי אפשרויות נמחקת |
| BR-065 | שפות סקר: עברית, English, العربية, Русский |
| BR-066 | תזכורת במייל: אף פעם / 24 / 48 (ברירת מחדל) / 72 / 168 שעות |
| BR-067 | טקסטים ניתנים לעריכה, עד 300 תווים כל אחד |
| BR-068 | קמפיין חדש תמיד נוצר פעיל |
| BR-069 | מחיקת קמפיין: **בעלים בלבד** |

**End Result:** קמפיין פעיל עם קישור קבוע `/r/<slug>` וקוד QR.

### FLOW-017: סקר הלקוח (דירוג → שאלות → תודה → גוגל)

**מטרה:** לאסוף דירוג ומשוב מכל לקוח, ולהפנות לקוח מרוצה לכתוב ביקורת בגוגל.
**Actors:** CUSTOMER, SYSTEM, BUSINESS (מקבל התראות)
**Trigger:** הלקוח סורק QR, פותח קישור, או לוחץ על בקשת דירוג (מייל / וואטסאפ / API).
**Preconditions:** הקמפיין פעיל, והעסק אינו מושהה (BR-070).

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | CUSTOMER | פותח את הקישור | מסך דירוג 1-5 כוכבים, בשפה ובמיתוג של העסק | אירוע `scan`. אם הגיע מהזמנה: ההזמנה "נפתחה" |
| 2 | CUSTOMER | בוחר דירוג | מעבר לשאלות שמתאימות לדירוג | Response נוצר (`sentiment` = מרוצה / לא מרוצה). אירוע `rate` |
| 3 | CUSTOMER | עונה, כותב הערה, ובאופן אופציונלי שם, טלפון, מייל, "אשמח שיחזרו אליי" | בדיקת שדות חובה | — |
| 4 | SYSTEM | שומרת | מעבר למסך תודה | Response `completed`. אירוע `complete` |
| 5a | SYSTEM | **מרוצה** | כרטיס "כתבו ביקורת בגוגל" + ההערה שלו מוכנה להעתקה + 3 צעדים. קישורים נוספים אם הוגדרו | — |
| 5b | SYSTEM | **לא מרוצה** | הודעת הבנה ו"מה קורה עכשיו". **בלי קישורים לביקורת ציבורית** | — |
| 6 | CUSTOMER | לוחץ על קישור ביקורת | מעבר לגוגל (או לפלטפורמה אחרת) | אירוע `review_click` (פעם אחת לכל פלטפורמה) |
| 7 | SYSTEM | התראות לעסק | Webhook (אם הוגדר). ללא מרוצה: Push + מייל (BR-075) | — |

**Alternative Flows**
- **קישור אישי של עובד** (`?e=<קוד>`): הדירוג משויך לעובד, ולא נשאלת שאלת "מי נתן שירות".
- **"מי נתן שירות?"** (אם הופעל בקמפיין): רשימת העובדים הפעילים.
- **שאלת הסכמה לפרסום:** מוצגת רק ללקוח מרוצה שכתב הערה. אם העסק הפעיל פרסום אוטומטי בווידג'ט, ההערה מתפרסמת מיד (FLOW-021).
- **פתיחה חוזרת של קישור תודה** (`/t/...`): מסך התודה מוצג שוב.
- **פתיחה חוזרת של קישור השאלות אחרי השלמה:** מפנה למסך התודה (אין מילוי כפול).

**Error / Failure Flows**

| מצב | התנהגות |
|---|---|
| קישור לא קיים | "הקישור לא נמצא" (404) |
| קמפיין לא פעיל או עסק מושהה | הודעת "הסקר לא פעיל" בשפת הקמפיין |
| דירוג לא חוקי (לא 1-5) | חזרה למסך הדירוג |
| שאלת חובה ריקה | הטופס חוזר עם סימון השדות (422) |
| מייל לא תקין | נשמר כריק (לא חוסם) |
| הרבה שליחות מאותה IP | "יותר מדי בקשות" (30 ל-10 דקות) |

**Business Rules**

| ID | חוק |
|---|---|
| BR-070 | סקר מקבל דירוגים רק כשהקמפיין פעיל והעסק אינו מושהה (`paused` / `unpaid`) |
| BR-071 | הערה עד 3,000 תווים, טקסט חופשי בשאלה עד 2,000, שם עד 100, טלפון עד 30 |
| BR-072 | לקוח לא מרוצה **לא** מקבל קישור לביקורת ציבורית במסך התודה (ראו OQ-030, Compliance) |
| BR-073 | זיהוי מבקר באמצעות עוגייה לשנה, לספירת סריקות ייחודיות |
| BR-074 | לחיצה על אותה פלטפורמה נספרת פעם אחת לכל משוב |
| BR-075 | התראה על לא מרוצה: רק אם "התראה על לקוח לא מרוצה" מופעלת בהגדרות |

**Status Changes (Response):** `נפתח (דירוג) → הושלם`. שאלון שלא הושלם נשאר כ"לא השלים סקר".
**End Result:** המשוב נשמר ומופיע ב"משוב מהסקר". מרוצה הופנה לגוגל. על לא מרוצה העסק קיבל התראה.

```
CUSTOMER → סורק QR / פותח קישור
SYSTEM → קמפיין פעיל ועסק לא מושהה? → NO: "הסקר לא פעיל"
CUSTOMER → דירוג 1-5
SYSTEM → דירוג ≥ סף?
   YES (מרוצה) → שאלות למרוצים → תודה + "כתבו בגוגל" + העתקת ההערה → GOOGLE
   NO (לא מרוצה) → שאלות ללא מרוצים + פרטי קשר → תודה "חוזרים אליך" (בלי קישור ציבורי)
                  → SYSTEM: Push + מייל לעסק (אם מופעל) → FLOW-020
```

### FLOW-020: טיפול במשוב מהסקר וסגירת מעגל

**מטרה:** לטפל בכל לקוח לא מרוצה לפני שהוא כותב ביקורת שלילית, ולבדוק אם הטיפול עזר.
**Actors:** OWNER / MANAGER, CUSTOMER, SYSTEM, EMAIL, AI SERVICE
**Trigger:** התראה על לקוח לא מרוצה, "משוב מהסקר" בתפריט, או פעולה דחופה ב"מה לעשות".

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | USER | פותח משוב | פרטים: דירוג, תשובות, הערה, פרטי קשר, עובד, מקור, תגיות AI | — |
| 2 | USER | "טיוטה ב-AI" (אופציונלי) | טיוטת תשובה אישית ללקוח | מכסת טיוטות AI |
| 3 | USER | יוצר קשר עם הלקוח (מחוץ למערכת), מעדכן סטטוס ומוסיף הערה פנימית | נשמר | `status`, `notes` |
| 4 | SYSTEM | סטטוס "טופל" על משוב שלילי | נוצר קישור "האם טיפלנו?". אם יש מייל ללקוח ו"מעקב אוטומטי" מופעל: נשלח אליו | Followup token, `followup_sent_at` |
| 5 | CUSTOMER | עונה "כן, נפתר" / "לא" | מסך תוצאה. "כן": מוצגים קישורי ביקורת (גוגל ונוספים). "לא": בלי קישורים | `recovered = 1/0` |
| 6 | SYSTEM | "לא" | מייל לעסק: "הלקוח ענה שהטיפול לא עזר" | — |

**Alternative Flows**
- **SLA:** משוב שלילי שנשאר "חדש" יותר מזמן הטיפול שהוגדר (ברירת מחדל 24 שעות, 0 = כבוי): מייל התראה פעם אחת, והתראה אדומה בדשבורד.
- **סינון ברשימה:** לפי מרוצה / לא מרוצה, סטטוס, חריגת זמן, תגית.
- **ייצוא CSV** של המשובים.
- **מחיקת משוב:** בעלים בלבד.
- **פרסום בווידג'ט:** סימון הערה חיובית (עם הסכמה) לפרסום (FLOW-021).

**Business Rules**

| ID | חוק |
|---|---|
| BR-085 | סטטוסים: חדש, בטיפול, טופל, סגור ללא טיפול |
| BR-086 | קישור "האם טיפלנו" נוצר פעם אחת לכל משוב. התשובה נקלטת פעם אחת. פתיחה חוזרת מציגה את התשובה הקיימת |
| BR-087 | התראת SLA נשלחת פעם אחת לכל משוב, ורק למשובים מ-30 הימים האחרונים |
| BR-088 | הערות פנימיות עד 5,000 תווים |

**Status Changes**

| Current Status | Action | New Status |
|---|---|---|
| חדש | המשתמש מתחיל לטפל | בטיפול |
| חדש / בטיפול | הבעיה נפתרה | טופל (+ שליחת "האם טיפלנו?") |
| כל סטטוס | סגירה בלי טיפול | סגור ללא טיפול |
| טופל | הלקוח ענה | `recovered` = כן / לא |

**End Result:** המשוב מטופל ומתועד. אחוז "לקוחות שהוחזרו" מתעדכן.

```
CUSTOMER → משוב שלילי
SYSTEM → Push + מייל לעסק (אם מופעל)
   ... עבר זמן הטיפול והסטטוס "חדש"? → מייל SLA + התראה בדשבורד
USER → פותח, (טיוטת AI), חוזר ללקוח, סטטוס "טופל"
SYSTEM → יש מייל ומעקב אוטומטי? → YES: שולחת "האם טיפלנו?"
CUSTOMER → כן / לא → "לא": מייל לעסק
```

### FLOW-022: עובדים ודירוג עובדים

**מטרה:** לראות מי מהעובדים מקבל את הדירוגים הטובים ביותר.
**Actors:** OWNER / MANAGER, CUSTOMER
**Trigger:** "הגדרות עסק" ← "דירוג עובדים" (הוצא מהתפריט; כתובת `/admin/leaderboard`).

| פעולה | מי | התנהגות |
|---|---|---|
| הוספה / עריכה של עובד | מנהל ומעלה | שם, פעיל / לא פעיל. לכל עובד קוד, קישור אישי ו-QR |
| מחיקת עובד | בעלים בלבד | — |
| דירוג | כל משתמש | דירוג ממוצע וכמות לכל עובד בתקופה. עובד נכנס לדירוג רק מ-3 דירוגים |
| השוואת סניפים | כל משתמש | Needs Verification מה בדיוק מוצג (OQ-026) |

**Business Rules:** BR-089: דירוג משויך לעובד דרך הקישור האישי, או דרך בחירה בסקר. BR-090: העובד המוביל בשבוע מופיע בדוח השבועי (מינימום 3 דירוגים).
