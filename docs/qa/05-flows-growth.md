### FLOW-023: מה לעשות: פעולות, ציון ובדיקת אתר

**מטרה:** רשימה אחת של כל מה שמקדם את העסק בגוגל מפות וב-AI: קודם הדחוף, אחריו תוכנית קידום עם ציון 0-100.
**Actors:** OWNER / MANAGER (צפייה: כל משתמש), SYSTEM
**Trigger:** "מה לעשות" בתפריט, או "לכל הפעולות" בדשבורד.
**Preconditions:** עסק פעיל. "מה לעשות" מוצג בתפריט תמיד.

**מבנה העמוד:**
1. **דחוף עכשיו** (רק כשיש): לחזור ללקוחות לא מרוצים · לענות לביקורות שמחכות (30 יום) · לחבר את העסק בגוגל · ליצור קמפיין ושלט QR.
2. **ציון הקידום:** טבעת 0-100, תווית, 4 פסי מסלול, ו"הכי שווה לעשות עכשיו" (3 פעולות).
3. **"על העסק, בשביל ה-AI":** שירותים עיקריים ומה מייחד (עד 600 תווים). פתוח כשריק.
4. **שלב 2** (כשהציון ≥ 85, FLOW-025).
5. **4 מסלולים**, ובכל אחד פעולות:

| מסלול | פעולות (מפתח) | בדיקה אוטומטית? | תדירות |
|---|---|---|---|
| פרופיל הגוגל | מילות מפתח בפרופיל (`keywords`) | כן: אורך התיאור, מספר קטגוריות, העיר בתיאור | פעם אחת |
| | פרטים מלאים (`basics`) | כן: שעות, טלפון, אתר, מאפיינים, תמונות | פעם אחת |
| | תמונות חדשות (`photos`) | לא | כל שבוע |
| | פוסט בגוגל (`posts`) | כן, בחיבור מלא: פוסט שפורסם השבוע מהמערכת | כל שבוע |
| | ביקורות חדשות, עם מילים (`reviews`) | כן: 4+ ב-30 יום | פעם אחת (מתעדכן) |
| | מענה לכל ביקורת (`replies`) | כן: 80%+ מ-180 יום | פעם אחת (מתעדכן) |
| | קישורי הזמנה והודעות (`booking`) | לא | פעם אחת |
| האתר | אופטימיזציה בסיסית (`site-seo`) | כן: בדיקת אתר | פעם אחת |
| | טלפון, כתובת ומפה (`site-nap`) | כן: בדיקת אתר | פעם אחת |
| | סימון עסק מקומי, Schema (`site-schema`) | כן: בדיקת אתר. הקוד מוכן להעתקה | פעם אחת |
| | שאלות ותשובות (`site-faq`) | כן, כשנמצא סימון FAQ | פעם אחת |
| | תוכן ייחודי (`site-content`) | לא | כל חודש |
| נוכחות ברשת | אינדקסים ואזכורים (`citations`) | לפי 8 אינדקסים שמסומנים ידנית: 5+ = בוצע | פעם אחת |
| | מידע עקבי בכל מקום (`consistent`) | לא | פעם אחת |
| | ביקורות בכמה פלטפורמות (`multi-reviews`) | לא | פעם אחת |
| | קישורים מאתרים אחרים (`backlinks`) | לא | כל חודש |
| | אזכורים בכתבות ורשימות (`mentions`) | לא. מציג את האתרים שה-AI הסתמך עליהם | כל חודש |
| נראות ב-AI | שאלות למעקב (`ai-questions`) | כן: יש שאלות | פעם אחת |
| | תוכן שעונה ישר על השאלות (`ai-content`) | כן, כשהעסק הוזכר ב-50%+ מהתשובות | פעם אחת |

| 6 | USER | מסמן אינדקס שנרשם בו | נספר לפעולת האינדקסים | Mark `dir:*` |

**Business Rules**

| ID | חוק |
|---|---|
| BR-100 | מצב פעולה: **בוצע** (בדיקה אוטומטית עברה, או סומן ידנית) · **חלקית** (בדיקה אוטומטית חלקית) · **לביצוע** |
| BR-101 | ציון = סכום משקלי הפעולות שבוצעו (חלקית = חצי) חלקי סך המשקלים × 100. אותה נוסחה לכל מסלול |
| BR-102 | פעולה שבועית מתאפסת כל יום ראשון (שעון ישראל). פעולה חודשית: בתחילת כל חודש |

| BR-104 | בדיקת האתר פותחת רק כתובות ציבוריות (לא רשת פנימית), בודקת כל הפניה מחדש (עד 5), וקוראת עד 2MB |
| BR-105 | בדיקת האתר חוזרת כשנכנסים לעמוד אחרי שבוע. **לא** רצה כתהליך רקע (OQ-027) |
| BR-106 | סימון ושינוי: מנהל ומעלה. VIEWER רואה בלי כפתורים |
| BR-107 | פעולה שנבדקה אוטומטית ועברה: אין לה כפתור "בוצע" |

**Error Flows (בדיקת אתר)**

| מצב | הודעה |
|---|---|
| כתובת לא תקינה או פנימית | "הכתובת לא תקינה או לא ציבורית." |
| האתר לא עונה או איטי | "האתר לא נפתח (לא עונה או איטי מדי)." |
| האתר מחזיר שגיאה | "האתר החזיר שגיאה (קוד)." |
| יותר מדי הפניות | "יותר מדי הפניות בין כתובות." |

**End Result:** הציון משקף את מה שבוצע. הדשבורד מציג את הציון ואת הצעד הבא.

```
USER → "מה לעשות"
SYSTEM → אתר לא נבדק שבוע? → בדיקה ברקע
SYSTEM → מחשבת מצב לכל פעולה (בדיקות אוטומטיות + סימונים) → ציון
USER → פותח פעולה → (AI כותב / מסמן "בוצע")
SYSTEM → ציון מתעדכן → ≥85? → שלב 2 נפתח
```
