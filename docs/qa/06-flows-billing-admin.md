### FLOW-035: רשת סניפים ומשתמש מוגבל לסניף

**מטרה:** עסק עם כמה סניפים רואה השוואה ביניהם, ועובד יכול להיות מוגבל לסניף אחד.
**Actors:** OWNER / MANAGER (כל הרשת), BRANCH MANAGER (משתמש משויך לסניף)
**Trigger:** "רשת הסניפים" (למעלה בתפריט כשיש 2+ סניפים פעילים, אחרת תחת "ניהול העסק").

| פעולה | מי | התנהגות |
|---|---|---|
| השוואת סניפים | כל משתמש לא מוגבל | טבלה: דירוג, ביקורות, מחכים לתשובה, אחוז מענה, בריאות פרופיל, מיקום במפות |
| עמוד סניף | כל משתמש (מוגבל: רק שלו) | המספרים של הסניף, ביקורות אחרונות |
| תבניות תשובה | מנהל ומעלה עורכים, כולם רואים | FLOW-014 |

**הגבלת סניף (Branch Gate):** משתמש לא-בעלים ששויך לסניף יכול לגשת **רק** ל:
- עמוד הסניף שלו
- ביקורות הגוגל של הסניף שלו (צפייה, ותשובה אם הוא מנהל)
- תבניות תשובה
- מעבר בין עסקים

כל עמוד אחר (GET) מפנה לעמוד הסניף שלו. כל פעולה אחרת (POST): "אין לך הרשאה לפעולה הזו" (403). ביקורת של סניף אחר: 404.

**Business Rules:** BR-150: הגבלת סניף חלה רק על מנהל וצפייה, אף פעם לא על בעלים. BR-151: מנהל סניף מקבל מיילים על ביקורות 1-3 כוכבים של הסניף שלו, ו-Push רק על הסניף שלו.
**Note:** "Network Manager" אינו תפקיד נפרד במערכת. מי שמנהל את הרשת הוא בעלים או מנהל של העסק.

### FLOW-037: בחירת מסלול ותשלום ב-iCount

**מטרה:** תשלום על מסלול דרך עמוד תשלום של iCount, והפעלה אוטומטית כשהתשלום מגיע.
**Actors:** BUSINESS OWNER, iCount (EXTERNAL), SYSTEM, GOFIVE ADMIN
**Trigger:** "התוכנית שלי" ← בחירת מסלול ומחזור (חודשי / שנתי) ← "שינוי מסלול" ← אישור.
**Preconditions:** בעלים בלבד. אמצעי התשלום הפעיל הוא iCount (אין Cardcom מוגדר). כתובת עמוד iCount מוגדרת למסלול ולמחזור.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | OWNER | בוחר מסלול ומחזור | עמוד אישור: מה משתנה, וכמה עולה (כולל סניפים) | — |
| 2 | OWNER | מאשר | נשמרת בקשה. מייל למנהלי המערכת. מעבר לעמוד התשלום של iCount | `plan_request` |
| 3 | OWNER | משלם ב-iCount (צריך להזין את המייל שאיתו נרשם) | — | — |
| 4 | iCount | שולח הודעת תשלום (IPN) לכתובת סודית ב-GoFive | SYSTEM מחפש התאמה: לפי מייל של מישהו מהצוות + סכום מדויק. אחרת: לפי סכום בלבד, אם רק עסק אחד ביקש את הסכום הזה ב-3 הימים האחרונים | Payment record |
| 5a | SYSTEM | **נמצאה התאמה** | המסלול נפתח (או הסניף נפתח). מייל למנהלי המערכת "תשלום התקבל והופעל" | `billing = active`, plan, cycle. הבקשה נמחקת |
| 5b | SYSTEM | **אין התאמה** | מייל למנהלי המערכת "לא הופעל אוטומטית". המנהל מפעיל ידנית בפאנל | `result = manual` |

**Alternative Flows**
- **בלי עמוד iCount מוגדר:** הבקשה נשמרת, והמשתמש רואה "קיבלנו את הבקשה". מנהל המערכת חוזר אליו (תשלום ידני).
- **מסלול "רשת" (בלי מחיר):** בקשה בלבד, בהצעת מחיר.
- **אותו IPN נשלח פעמיים:** נשמר פעם אחת, בלי הפעלה כפולה.

**Business Rules**

| ID | חוק |
|---|---|
| BR-160 | מחיר לפרופיל גוגל: גוגל ₪99, גוגל+AI ₪149 לחודש (כולל מע"מ). כל פרופיל נוסף ‎-20% |
| BR-161 | שנתי: משלמים על 10 חודשים ומקבלים 12 |
| BR-162 | IPN בלי הסוד הנכון: 404, בלי שום שינוי |
| BR-163 | IPN ריק (iCount בודק את הכתובת): לא נשמר |
| BR-164 | התאמה לפי סכום בלבד: רק כשיש עסק אחד בדיוק שמחכה לאותו סכום, ושביקש ב-3 הימים האחרונים |
| BR-165 | **במסלול iCount, החיוב החוזר מתבצע ב-iCount.** בלי ביטול, העסק נשאר פעיל עד שמנהל מערכת משהה אותו. אחרי ביטול ב-GoFive, העסק נשאר פעיל עד סוף התקופה ששולמה (חודש או שנה מהתשלום שפתח את המסלול) ואז מושהה אוטומטית. ההוראה הקבע ב-iCount עצמה מבוטלת ב-iCount (L-01) |

**Status Changes**

| Current Status | Action | New Status |
|---|---|---|
| trial / unpaid / paused | תשלום הותאם, או הפעלה ידנית | active |
| active | מנהל מערכת "השהיה" | paused |

**End Result:** העסק `active` במסלול ששולם. המנהל קיבל מייל אישור.

```
OWNER → בוחר מסלול → מאשר
SYSTEM → שומרת בקשה + מייל למנהל → מפנה ל-iCount
OWNER → משלם ב-iCount
iCount → IPN → SYSTEM: סוד נכון? → NO: 404
              → התאמה לפי מייל + סכום? → YES: הפעלה + מייל "הופעל"
              → NO → התאמה לפי סכום (עסק יחיד, 3 ימים)? → YES: הפעלה / NO: מייל "להפעיל ידנית"
GOFIVE ADMIN → (אם צריך) הפעלה ידנית בפאנל
```
