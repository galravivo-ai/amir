### FLOW-008: חיבור מלא לגוגל (OAuth) ובחירת סניפים

**מטרה:** חיבור חשבון הגוגל שמנהל את פרופיל העסק, כדי לקבל ביקורות, נתוני פרופיל (צפיות, שיחות, חיפושים), ולענות ולפרסם ישירות לגוגל.
**Actors:** OWNER / MANAGER, GOOGLE, SYSTEM
**Trigger:** "חיבור לגוגל" בתפריט (מוצג רק כשעדיין לא מחוברים), או כרטיס החיבור בדשבורד.
**Preconditions:** מנהל ומעלה. Google OAuth מוגדר בשרת. למשתמש יש חשבון גוגל שמנהל את פרופיל העסק.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | USER | "התחברות עם חשבון הגוגל של העסק" | מעבר למסך ההרשאות של גוגל | עוגיית state (10 דק') קשורה לעסק הנוכחי |
| 2 | GOOGLE | המשתמש מאשר הרשאה לניהול העסקים | חזרה ל-GoFive | — |
| 3 | SYSTEM | שומרת את ההרשאה ומושכת את רשימת הסניפים מגוגל | "החשבון חובר. סמנו את הסניפים..." | Connection נשמר (מוצפן). סניפים נוצרים **כבויים** |
| 4 | SYSTEM | אם יש סניף אחד בלבד | מסנכרנת ביקורות מיד, ונתוני פרופיל (18 חודש אחורה) ברקע | Reviews, Metrics |
| 5 | USER | מסמן סניפים לעקוב אחריהם, ובאופן אופציונלי מקשר כל סניף לקמפיין | סניף שהופעל נטען מיד (ביקורות ונתונים), בלי לחכות לסבב הבא | `enabled = true`. אם לקמפיין אין קישור גוגל, הוא מתמלא מהסניף |
| 6 | SYSTEM | מציגה "מתי מגיעים הנתונים" (Data Arrival) | ציר זמן: מה הגיע, מה בדרך, מה נכשל | — |

**Alternative Flows**
- **הסניף השני והלאה בחשבון משלם:** הסניף לא נפתח מיד. הוא ממתין לתשלום (FLOW-010).
- **בניסיון, בקישור התנסות, בדמו, או אצל מנהל מערכת:** כל הסניפים נפתחים בלי תשלום.
- **אין גישה לחשבון הגוגל:** מעקב לפי קישור (FLOW-009).

**Error / Failure Flows**

| מצב | התנהגות |
|---|---|
| המשתמש ביטל בגוגל | "החיבור בוטל בגוגל." |
| state לא תואם, פג, או החיבור התחיל בעסק אחר | "פג תוקף החיבור, נסו שוב." |
| בחשבון הגוגל אין סניפים | מוצגת הודעה "לא נמצאו סניפים בחשבון" (לפי המדריך). ניסוח מדויק: Needs Verification (OQ-016) |
| שגיאה מגוגל | הודעה בעברית לפי סוג השגיאה (הרשאה, מכסה, שגיאה כללית) |
| הטעינה הראשונה נכשלה | נרשם ביומן. מופיע כ"נכשל" ב-Data Arrival עם הסבר |
| Google OAuth לא מוגדר | עמוד הסבר. למנהל מערכת מוצגת בדיקת הגדרה עם ה-Redirect URI |

**Business Rules**

| ID | חוק |
|---|---|
| BR-030 | סניף חדש מגוגל נוצר כבוי. רק מה שהמשתמש סימן נסרק ונספר בתשלום |
| BR-031 | החיבור שייך לעסק, לא למשתמש. חשבון גוגל אחד יכול לשרת כמה עסקים |
| BR-032 | נתוני הפרופיל מגיעים מגוגל באיחור של כמה ימים. הימים האחרונים מתמלאים בהדרגה |
| BR-033 | חיפושי "איך מצאו אתכם" מגיעים לפי חודש, אחרי סוף החודש |

**Status Changes (סניף)**

| Current Status | Action | New Status |
|---|---|---|
| — | נמשך מגוגל | כבוי (`enabled=0`) |
| כבוי | סימון, בלי צורך בתשלום | פעיל (`enabled=1`) |
| כבוי | סימון, צריך תשלום | ממתין לתשלום (`pending_pay=1`) |
| פעיל | ביטול סימון | כבוי (הנתונים נשארים) |

**End Result:** העסק מחובר, הסניפים שנבחרו פעילים, הביקורות והנתונים נטענים, והדשבורד מתמלא.

```
USER → "התחברות עם גוגל"
GOOGLE → אישור? → NO: "החיבור בוטל" / YES ↓
SYSTEM → שומרת הרשאה, מושכת סניפים (כבויים)
   סניף אחד? → YES: סנכרון ביקורות מיד + נתונים ברקע
USER → מסמן סניפים
SYSTEM → צריך תשלום? → YES: ממתין לתשלום (FLOW-010) / NO: פעיל + טעינה מיידית
SYSTEM → Data Arrival מתעדכן
```

**Technical Notes:** ההרשאה נשמרת מוצפנת. הסנכרון הקבוע: ביקורות כל 30 דק', נתונים פעם ביום (FLOW-048).

### FLOW-009: מעקב אחרי עסק לפי קישור (בלי חיבור לגוגל)

**מטרה:** לעקוב אחרי עסק בלי גישה לחשבון הגוגל שלו, כדי לקבל ביקורות ודירוג.
**Actors:** OWNER / MANAGER, SerpApi (EXTERNAL), SYSTEM
**Trigger:** בעמוד "חיבור לגוגל": הדבקת קישור מגוגל מפות, או שם עסק ועיר.
**Preconditions:** מנהל ומעלה. SerpApi מוגדר.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | USER | מדביק קישור או כותב שם + עיר | חיפוש | — |
| 2 | SYSTEM | התאמה ישירה | העסק נוסף מיד | Location (`source=serp`) |
| 3 | SYSTEM | כמה תוצאות | רשימה לבחירה | — |
| 4 | USER | בוחר עסק | העסק נוסף | Location |
| 5 | SYSTEM | טעינה ראשונה ברקע (שנה אחורה, עד דקה) | "העסק נוסף. הביקורות נטענות עכשיו ברקע" | Reviews |

**Error / Failure Flows**

| מצב | התנהגות |
|---|---|

| הטעינה הראשונה נכשלה | שגיאה נשמרת על הסניף ומוצגת ב-Data Arrival |

**Business Rules**

| ID | חוק |
|---|---|

| BR-037 | הוספת סניף בחשבון משלם יוצרת סניף "ממתין לתשלום" (FLOW-010) |

**End Result:** העסק מופיע ברשימת הסניפים, והביקורות שלו בעמוד הביקורות (לקריאה בלבד, עם קישור לענות בגוגל).

### FLOW-010: הוספת סניף בתשלום

**מטרה:** בחשבון משלם, כל סניף נוסף משולם לפני שהוא נפתח (20% הנחה מהמחיר).
**Actors:** OWNER / MANAGER, iCount (EXTERNAL), GOFIVE ADMIN, SYSTEM
**Trigger:** הפעלת סניף נוסף (FLOW-008) או הוספת עסק לפי קישור (FLOW-009) בחשבון משלם.
**Preconditions:** העסק `active` ובמסלול עם מחיר, יש כבר סניף פעיל, התשלום אינו ב-Cardcom, והעסק אינו פיילוט, דמו או של מנהל מערכת.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | USER | מפעיל סניף נוסף | "הסניף נוסף וממתין לתשלום..." | `pending_pay = 1` |
| 2 | USER | "לתשלום" ליד הסניף | מייל למנהל המערכת. מעבר לעמוד התשלום של iCount לסניף (אם מוגדר), אחרת הודעה "קיבלנו את הבקשה" | `pay_requested_at` |
| 3 | iCount | התשלום עבר, iCount שולח הודעה (IPN) | התאמה אוטומטית לסניף (FLOW-037) | סניף נפתח |
| 3א | GOFIVE ADMIN | אם לא הותאם אוטומטית: "הפעלה" בפאנל | הסניף נפתח | `enabled = 1`, `pending_pay = 0` |
| 4 | SYSTEM | שולחת מייל "הסניף נפתח" | — | — |

**Business Rules**

| ID | חוק |
|---|---|
| BR-038 | מחיר סניף: מחיר המסלול פחות 20% (גוגל ₪79, גוגל+AI ₪135 לחודש; בשנתי פי 10) |
| BR-039 | ב-Cardcom הסניף נפתח מיד ומחויב בחידוש הבא |
| BR-040 | תשלום אחד פותח את הסניף שמחכה הכי הרבה זמן באותו עסק |

**Status Changes:** `כבוי → ממתין לתשלום → (תשלום / הפעלה ידנית) → פעיל`. ביטול סימון של סניף ממתין מחזיר אותו לכבוי.

**End Result:** הסניף פעיל, נסרק ומופיע בכל העמודים, ונספר בחישוב המחיר.

### FLOW-013: ביקורות גוגל ותשובה לביקורת
