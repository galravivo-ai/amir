## 4. אפיון ה-Flows

### מוסכמות לכל ה-Flows
- **USER** בטבלאות = משתמש מחובר בעסק. כשהתפקיד חשוב, כתוב OWNER / MANAGER / VIEWER.
- **"מנהל ומעלה"** = MANAGER או OWNER. **"בעלים בלבד"** = OWNER.
- **חשבון דמו:** כל פעולת שמירה (POST) בחשבון הדמו נחסמת עם ההודעה "זה חשבון דמו לצפייה בלבד" (BR-002). לא חוזר על זה בכל Flow.
- **CSRF:** כל טופס במערכת נושא אסימון. טופס שנשלח מדף ישן אחרי יציאה וכניסה מחדש נדחה עם "פג תוקף הטופס. רעננו את הדף ונסו שוב" (BR-003).

**חוקים כלליים:**

| ID | חוק |
|---|---|
| BR-001 | עסק "ממתין לתשלום ראשון" (unpaid) רואה רק את "התוכנית שלי". כל עמוד אחר מפנה לשם. פעולה אחרת מחזירה "כדי להתחיל, בוחרים מסלול" |
| BR-002 | חשבון דמו: צפייה בלבד, כל שמירה נחסמת |
| BR-003 | כל טופס מחייב אסימון CSRF תקף של הסשן הנוכחי |
| BR-004 | מנהל מערכת: העסקים שלו תמיד פעילים, בלי ניסיון ובלי חיוב. עסק כזה מועבר אוטומטית למסלול עם כל הפיצ'רים |
| BR-005 | משתמש שהעסק האחרון שלו נמחק מקבל אוטומטית עסק חדש בשם "העסק שלי" |

### FLOW-001: הרשמה במייל

**מטרה:** פתיחת חשבון ועסק ראשון, והתחלת תקופת ניסיון או המתנה לתשלום.
**Actors:** VISITOR, SYSTEM, EMAIL SERVICE
**Trigger:** VISITOR לוחץ "הרשמה" או "התחילו ניסיון" באתר.
**Preconditions:** ההרשמה פתוחה (ALLOW_SIGNUP, או שאין עדיין אף משתמש). כשההרשמה סגורה, `/register` מפנה ל-`/login`.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | VISITOR | פותח `/register` | טופס: שם, אימייל, סיסמה, שם העסק, אישור תנאים (חובה), הסכמה לדיוור (לא חובה) | — |
| 2 | VISITOR | ממלא ושולח | בדיקות תקינות (ראו Business Rules) | — |
| 3 | SYSTEM | יוצר משתמש ועסק | המשתמש הוא **בעלים** של העסק | User + Business נוצרים |
| 4 | SYSTEM | קובע מצב התחלתי לעסק | לפי הגדרות התשלום (BR-013) | `billing = trial` (ניסיון) או `unpaid` |
| 5 | SYSTEM | מתחיל סשן | המשתמש מחובר | Session (30 יום) |
| 6 | SYSTEM | שולח מדריך התחלה במייל (ברקע) | — | מייל `welcome_guide` |
| 7 | SYSTEM | מפנה | בעסק בניסיון: לדשבורד. בעסק unpaid: ל"התוכנית שלי" (BR-001) | — |

**Alternative Flows**
- **הרשמה דרך קישור התנסות** (`/register?pass=...`): העסק מקבל את המסלול ומספר הימים של הקישור, ללא כרטיס. ראו FLOW-041.
- **המשתמש הראשון במערכת חדשה:** הופך למנהל מערכת, אלא אם הוגדר SUPERADMIN_EMAILS. מנהל מערכת מופנה ל-`/superadmin`, ולא מקבל מייל מדריך (BR-004).
- **מייל שמוגדר כמנהל מערכת:** העסק נוצר במסלול "עסקי" ופעיל.

**Error / Failure Flows**

| מצב | התנהגות |
|---|---|
| שדה חובה חסר | "יש למלא את כל השדות" |
| אימייל לא תקין | "אימייל לא תקין" |
| סיסמה קצרה מ-8 תווים | "סיסמה חייבת להכיל לפחות 8 תווים" |
| לא אושרו התנאים | "יש לאשר את תנאי השימוש ומדיניות הפרטיות" |
| "שם העסק" זהה לסיסמה או לאימייל, או מכיל @ | "נא לכתוב בשדה 'שם העסק' את השם של העסק..." (הגנה ממילוי אוטומטי של הדפדפן) |
| אימייל כבר רשום | "האימייל כבר רשום. היכנסו לחשבון..." |
| יותר מדי ניסיונות מאותה כתובת IP | חסימה זמנית (Rate limit) |
| שליחת המייל נכשלה | ההרשמה מצליחה בכל זאת. המייל לא נשלח (רישום ביומן בלבד) |

**Business Rules**

| ID | חוק |
|---|---|
| BR-010 | סיסמה: לפחות 8 תווים |
| BR-011 | אישור תנאים חובה. הסכמה לדיוור נפרדת ולא חובה |
| BR-012 | אימייל ייחודי במערכת (לא תלוי אותיות גדולות/קטנות) |
| BR-013 | ניסיון: 7 ימים כברירת מחדל (SIGNUP_TRIAL_DAYS משנה, 0 מבטל). כש-Cardcom פעיל, העסק מתחיל כ-unpaid, והניסיון מתחיל רק כשנשמר כרטיס |
| BR-014 | מסלול הניסיון: "גוגל + AI" (pro) |

**Status Changes**

| Current Status | Action | New Status |
|---|---|---|
| — | הרשמה, ניסיון פעיל | `trial` |
| — | הרשמה, בלי ניסיון | `unpaid` (מושהה, ממתין לתשלום) |
| — | הרשמה דרך קישור התנסות | `trial` + `pilot` |

**End Result:** משתמש מחובר, בעלים של עסק אחד. העסק בניסיון (עם מונה ימים) או ממתין לבחירת מסלול.

```
VISITOR → ממלא טופס הרשמה
   ↓
SYSTEM → הנתונים תקינים?
   NO  → הודעת שגיאה בטופס, הערכים נשמרים בטופס
   YES ↓
SYSTEM → יוצר משתמש + עסק → קישור התנסות? → YES: ניסיון לפי הקישור
                                          → NO: ניסיון פעיל? → YES: trial 7 ימים / NO: unpaid
   ↓
SYSTEM → סשן + מייל מדריך (ברקע)
   ↓
USER → דשבורד (trial) / "התוכנית שלי" (unpaid)
```

### FLOW-002: הרשמה וכניסה עם גוגל

**מטרה:** כניסה או הרשמה בלי סיסמה, דרך חשבון גוגל.
**Actors:** VISITOR, GOOGLE, SYSTEM
**Trigger:** לחיצה על "התחברות עם Google" במסך כניסה או הרשמה.
**Preconditions:** Google OAuth מוגדר בשרת. בלי זה הכפתור לא מוצג, וכתובות הגוגל מפנות ל-`/login`.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | VISITOR | לוחץ "התחברות עם Google" | מעבר למסך ההסכמה של גוגל | עוגיית state לאימות החזרה |
| 2 | GOOGLE | מאשר את המשתמש | חזרה ל-GoFive עם אימייל ושם | — |
| 3 | SYSTEM | בודק אם האימייל קיים | **קיים:** כניסה (כולל 2FA אם מופעל), FLOW-003 | Session |
| 4 | SYSTEM | **לא קיים:** מפנה ל"השלמת הרשמה" | טופס: שם העסק, אישור תנאים, דיוור. האימייל מגוגל קבוע | — |
| 5 | VISITOR | שולח | כמו FLOW-001 מצעד 3 | משתמש בלי סיסמה |

**Alternative Flows:** משתמש שנרשם בגוגל ורוצה סיסמה משתמש ב"שכחתי סיסמה" (FLOW-004).

**Error / Failure Flows**

| מצב | התנהגות |
|---|---|
| המשתמש ביטל במסך של גוגל | חזרה לכניסה. הודעה מדויקת: Needs Verification (OQ-010) |
| state לא תואם או פג (10 דק') | חזרה לכניסה |
| `redirect_uri_mismatch` בגוגל | שגיאה במסך של גוגל. תקלת הגדרה, לא באג בקוד |
| ההרשמה סגורה | לא נוצר חשבון חדש, מפנה להרשמה |

**Business Rules**

| ID | חוק |
|---|---|
| BR-015 | חשבון שנוצר בגוגל אינו נכנס בסיסמה עד שנקבעה סיסמה דרך איפוס |
| BR-016 | כל עוד האפליקציה לא אומתה סופית בגוגל, המשתמש עלול לראות מסך אזהרה של גוגל (Needs Verification, OQ-011) |

**End Result:** משתמש מחובר. אם הוא חדש, נוצר לו עסק כמו ב-FLOW-001.

### FLOW-003: כניסה, אימות דו-שלבי ויציאה

**מטרה:** גישה מאובטחת למערכת.
**Actors:** USER, SYSTEM
**Trigger:** כניסה ל-`/login`, או ניסיון לגשת לעמוד מוגן בלי סשן (הפניה ל-`/login`).
**Preconditions:** למשתמש יש חשבון.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | USER | מזין אימייל וסיסמה | בדיקת פרטים | — |
| 2 | SYSTEM | פרטים נכונים, 2FA כבוי | סשן נפתח. מנהל מערכת מופנה ל-`/superadmin`, כל השאר ל-`/admin` | Session (30 יום) |
| 3 | SYSTEM | פרטים נכונים, 2FA מופעל | מעבר למסך קוד (תוקף 5 דקות) | Login challenge |
| 4 | USER | מזין קוד מהאפליקציה או קוד גיבוי | קוד תקין: סשן נפתח | קוד גיבוי נמחק אחרי שימוש |
| 5 | USER | "יציאה" (בתפריט) | הסשן נמחק, מעבר לכניסה | Session נמחק |

**Error / Failure Flows**

| מצב | התנהגות |
|---|---|
| פרטים שגויים | "אימייל או סיסמה שגויים" (לא מגלה איזה מהשניים) |
| 5 כישלונות לאותו אימייל מאותה IP | חסימה ל-5 דקות: "יותר מדי ניסיונות, נסו שוב בעוד כמה דקות" |
| קוד 2FA שגוי | "הקוד לא נכון או שפג תוקפו" |
| 5 קודים שגויים, או עברו 5 דקות | חזרה למסך הכניסה |
| קוד 2FA שכבר שומש | נדחה (כל קוד פעם אחת) |

**Business Rules**

| ID | חוק |
|---|---|
| BR-017 | סשן תקף 30 יום |
| BR-018 | נעילה: 5 ניסיונות כושלים ← 5 דקות, לפי IP + אימייל |
| BR-019 | 2FA: קוד TOTP, או אחד מ-10 קודי גיבוי חד-פעמיים |
| BR-020 | פרמטר `next` מכבד רק כתובות הצטרפות לצוות (`/join/...`), כדי למנוע הפניה לאתר זר |

**End Result:** המשתמש מחובר ונמצא בעסק האחרון שבחר.

```
USER → אימייל + סיסמה
SYSTEM → נכון?
   NO  → שגיאה (5 פעמים → נעילה 5 דק')
   YES → 2FA מופעל?
          NO  → סשן → /admin או /superadmin
          YES → מסך קוד → קוד נכון? → YES: סשן / NO: שגיאה (5 פעמים → חזרה לכניסה)
```

### FLOW-004: איפוס סיסמה

**מטרה:** כניסה מחדש כשהסיסמה נשכחה, או קביעת סיסמה לחשבון שנפתח בגוגל.
**Actors:** USER, SYSTEM, EMAIL SERVICE
**Trigger:** "שכחתי סיסמה" במסך הכניסה.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | USER | מזין אימייל | תמיד: "אם האימייל רשום, נשלח אליו קישור" | — |
| 2 | SYSTEM | אם האימייל רשום | שולח קישור איפוס | Reset token (תוקף שעה) |
| 3 | USER | פותח את הקישור | טופס: סיסמה חדשה + אימות | — |
| 4 | USER | שולח | הסיסמה מוחלפת | Password updated. הטוקן מסומן כמשומש |

**Error / Failure Flows**

| מצב | התנהגות |
|---|---|
| אימייל לא רשום | אותה הודעה כמו לרשום (לא חושף) |
| קישור פג (שעה) או משומש | Needs Verification: ההודעה המדויקת (OQ-012) |
| הסיסמאות לא תואמות / קצרה | שגיאה בטופס |

**Business Rules:** BR-021: קישור איפוס תקף לשעה ולשימוש אחד.
**Open:** האם איפוס סיסמה מנתק סשנים קיימים? Needs Verification (OQ-013).

### FLOW-005: ניהול החשבון האישי

**מטרה:** עדכון פרטים אישיים והגדרות אבטחה.
**Actors:** USER (כל תפקיד)
**Trigger:** "החשבון שלי" בתפריט.

| פעולה | התנהגות | נשמר |
|---|---|---|
| שינוי שם / אימייל | עדכון הפרטים | User |
| שינוי סיסמה | מחייב סיסמה נוכחית | Password |
| שפת ממשק | עברית / English, משפיע על כל המסכים והמיילים למשתמש הזה | `user.lang` |
| דיוור | הסכמה לעדכונים שיווקיים (הודעות שירות נשלחות תמיד) | `marketing` |
| שינוי שם עסק | לכל עסק שהמשתמש בעלים בו | Business name |
| הפעלת 2FA | QR לאפליקציה, אימות קוד, הצגת 10 קודי גיבוי **פעם אחת** | `totp_enabled` |
| כיבוי 2FA | מחייב סיסמה + קוד (או קוד גיבוי) | `totp_enabled = false` |
| התראות לטלפון | הפעלה, כיבוי ושליחת בדיקה, לכל מכשיר בנפרד (FLOW-034) | Push subscription |
| התקנה כאפליקציה | כפתור (FLOW-034) | — |

**Error Flows:** קוד 2FA שגוי בהפעלה: "הקוד לא תואם. ודאו שהשעה בטלפון נכונה". כיבוי עם סיסמה או קוד שגויים: "הסיסמה או הקוד לא נכונים".
**Open:** שינוי אימייל: האם נדרש אימות לכתובת החדשה, והאם יש בדיקת ייחודיות? Needs Verification (OQ-014).

### FLOW-006: הזמנת צוות, הצטרפות ושיוך לסניף

**מטרה:** הוספת עובדים לעסק עם הרשאה מתאימה, ואפשרות להגביל עובד לסניף אחד.
**Actors:** BUSINESS OWNER, USER (המוזמן), EMAIL SERVICE
**Trigger:** OWNER נכנס ל"ניהול העסק" ← "צוות".
**Preconditions:** בעלים בלבד.

| Step | Actor | Action | System Response | Data / Status Change |
|---|---|---|---|---|
| 1 | OWNER | מזין אימייל, בוחר תפקיד (בעלים / מנהל / צפייה) ובאופן אופציונלי סניף | בדיקות | — |
| 2 | SYSTEM | יוצר הזמנה | שולח מייל, ומציג את הקישור פעם אחת על המסך (לשיתוף ידני) | Team invite (תוקף 7 ימים) |
| 3 | USER | פותח את הקישור | **מחובר עם אותו אימייל:** מצטרף מיד. **לא מחובר:** טופס הרשמה עם האימייל קבוע | — |
| 4 | SYSTEM | מאשר הצטרפות | המשתמש נוסף לעסק, והעסק נבחר אצלו | Membership (role, branch) |
| 5 | OWNER | משנה תפקיד, משייך לסניף או מסיר | עדכון | Membership updated |

**Error / Failure Flows**

| מצב | התנהגות |
|---|---|
| אימייל לא תקין | "אימייל לא תקין" |
| המשתמש כבר בצוות | "המשתמש כבר בצוות" |
| קישור פג או נוצל | "ההזמנה פגה או כבר נוצלה" (410) |
| מחובר עם אימייל אחר | "ההזמנה שייכת לאימייל אחר" (403) |
| הסרת הבעלים האחרון | "אי אפשר להסיר את הבעלים האחרון" |
| הורדת הבעלים האחרון לתפקיד אחר | "חייב להישאר לפחות בעלים אחד" |

**Business Rules**

| ID | חוק |
|---|---|
| BR-022 | תפקידים: בעלים > מנהל > צפייה. כל הרשאה ניתנת "מתפקיד X ומעלה" |
| BR-023 | הזמנה תקפה 7 ימים ולשימוש אחד |
| BR-024 | בעלים לא משויך לסניף. שיוך לסניף נשמר רק למנהל או צפייה |
| BR-025 | חייב להישאר לפחות בעלים אחד בעסק |
| BR-026 | מספר המשתמשים לא מוגבל באף מסלול (Infinity) |

**Status Changes:** הזמנה: `pending → accepted` או `pending → expired` (7 ימים) או `pending → deleted` (בוטלה ע"י הבעלים).
**End Result:** המשתמש החדש רואה את העסק לפי ההרשאה שלו. משתמש משויך לסניף רואה רק את הסניף (FLOW-035).

### FLOW-007: ריבוי עסקים ומעבר בין עסקים

**מטרה:** משתמש אחד יכול להיות שייך לכמה עסקים.
**Actors:** USER
**Trigger:** "הוספת עסק" ב"הגדרות עסק" (POST `/admin/businesses`), או הצטרפות לצוות של עסק אחר.

| Step | Actor | Action | System Response | Data |
|---|---|---|---|---|

| 2 | USER | בוחר עסק מהרשימה בכרטיס העסק בתפריט | כל המערכת עוברת לעסק הנבחר | עוגיית עסק נבחר |
